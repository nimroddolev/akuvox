# v1.0.0-beta3

## Fixes

- Preserve registered phone-number digits during SMS setup and reauthentication. Retry without a leading zero only after SmartPlus explicitly rejects the original number as unregistered; timeouts and rate limits never trigger another SMS. Addresses #124.
- Refresh email sessions using the correct refresh-token field, retain email login context during setup and reauthentication, and persist rotated credentials. Includes the fixes from #126 relevant to #95.
- Provide isolated camera restreams and bounded snapshot caching for HomeKit. Includes #121.
- Accept legacy temporary-key timestamps containing AM/PM in API responses and saved sensor data. This addresses the date-parsing failure shown in #93, but does not establish the cause of the polling failures in that report.

## Documentation and maintenance

- Add an Apple Home guide and example package for camera viewing, relay unlocking, and SIP-based doorbell notifications (#125).
- Add regression coverage for opening Configure with Home Assistant's read-only options-flow entry property (#131). That compatibility fix was already included in earlier beta releases.
- Update development dependencies to Home Assistant 2026.11.2, PyTurboJPEG 2.6.1, and Ruff 0.17.5, and update the release action to 3.0.4.

## Remaining limitations

- Built-in immediate SIP call detection and call rejection are not implemented. The guide uses the separate ha-sip add-on for ringing notifications.
- Logging into Home Assistant and the mobile app with the same SmartPlus account can still invalidate the other session; a dedicated family-member account avoids sharing the same login.
- #99 still needs confirmation of expected devices on the current beta. #26 needs current Australian-account diagnostics. #83 has no confirmed cause for modem restarts.

This is a prerelease. In HACS, enable prerelease versions and select this version once it has been published with its integration ZIP.
